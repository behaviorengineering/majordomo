# Typology cluster: mechanical walk vs RLM

*Decision note for context-digest clustering. Not PR file-batch clustering (`internal/cluster`).*

## Decision

**Structure is mechanical. Judgment is a small LLM packet. RLM is not the default for clustering.**

1. Walk from delivery doors (`entrypoint`, `server`) on the import graph.
2. Parse that reachability set with role stop signs into a cluster seed (door-private vs shared, product clumps, library candidates).
3. Ask an LLM only for what the parse cannot decide: slice names/objectives, ambiguous split-vs-keep, and boundary-debt counsel.
4. Prefer ordinary CoT on that shrunk packet. Use RLM only when the packet is still too large to dump safely.
5. Keep emitting `cluster_proposal.md` for the existing refine step. Do not invent catalog YAML in the walk.

Roles (including post-RLM role validation) are brakes on ownership claims, not the grouping driver. The walk follows the programs; roles forbid bad merges (for example entrypoint with server, dto swallowed by an aggregator, exec_runner treated as CLI furniture).

## Why

A recursive language model shines when the model must **pull evidence on demand** across a large variable space (as with per-package role validation against AST context). Clustering’s first job is different: **reachability and shared-vs-private** are graph algorithms. Putting that walk inside RLM adds cost without clearer structure.

Today’s one-shot cluster CoT fails when the prompt is crowded, not because we lack a REPL. Shrinking the packet with a door-started mechanical walk fixes the crowding. After that, CoT is usually enough.

## Algorithm (target)

```text
package_roles + graph
  → doors = packages with role entrypoint | server
  → for each door: mechanical reachability walk (imports / labeled edges)
  → parse:
       - packages reached by one door only → door-private candidates
       - packages reached by multiple doors → shared / library candidates
       - role stop signs block ownership across forbidden pairs
       - connected aggregator/adapter components → product clumps
  → LLM (CoT, small packet): name clumps, argue splits, write debt counsel
  → assemble cluster_proposal.md
  → typology_refine → refined catalog YAML (unchanged contract)
```

Two doors never merge. Shared packages are not “won” by the first walk; they stay shared unless evidence says otherwise.

## What RLM still owns elsewhere

- **Package role validation** (already): budgeted inspect of AST context per package, agree/disagree with mechanical roles.
- **Cluster RLM (optional later):** only if a judgment packet remains large after the mechanical shrink (many packages, thick contracts). Not for the walk itself.

## Out of scope

- Replacing mechanical Stage 1/2 roles with LLM-first classification
- One RLM over the whole repo for cluster
- Changing human-intervention or SliceBinding passes in this note

## Status

Seed implemented in Typology `v0.0.19` (`BuildMechanicalGrouping` door walks). Majordomo still uses `typology_cluster` CoT for naming, splits, and debt on that seed. Cluster RLM remains out of scope.
