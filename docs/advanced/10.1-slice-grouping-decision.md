# Slice grouping: mechanical walk vs RLM

*Decision note for context-digest slice grouping (membership). Not PR file-batch clustering (`internal/cluster`).*

## Decision

**Structure is mechanical. Membership certainty is an RLM audit. CoT proposes; it does not self-certify.**

1. Walk from delivery doors (`entrypoint`, `server`) on the import graph.
2. Parse that reachability set with role stop signs into a cluster seed (door-private vs shared, product clumps, library candidates).
3. Write `mechanical_grouping.yaml` from the door-walk seed in Go.
4. Ask `typology_slice_grouping` CoT for optional merge rows only: flat parallel strings `merge_ids`, `merge_packages`, and `merge_intents` (comma / semicolon separated; literal `none` when proposing no folds). Go composes `slice_grouping_proposal.yaml`. No markdown counsel in this pass.
5. Run **one** `typology_slice_grouping_audit` RLM Completes over the **full** proposed-merge list (not one call per row). The auditor is a challenger: `accept` | `overlay` | `reject` with why and evidence quotes. It MUST NOT invent a better map.
6. CoT revises only rejected rows (sticky by sorted package set, so a rename like `git` → `forge` cannot re-litigate). Unresolved rejects demote to teaching nicknames.
7. `typology_slice_catalog` emits catalog YAML only and may fold packages only when the verdict is `accept`. Overlay/reject stay separate package owners. Journey markdown comes later from human-intervention after architecture.

Roles (including post-RLM role validation) are brakes on ownership claims, not the grouping driver. The walk follows the programs; roles forbid bad merges (for example entrypoint with server, dto swallowed by an aggregator, exec_runner treated as CLI furniture).

## Why

A recursive language model shines when the model must **pull evidence on demand** across a large variable space (as with per-package role validation against AST context). Clustering’s first job is different: **reachability and shared-vs-private** are graph algorithms. Putting that walk inside RLM adds cost without clearer structure.

Theme merges (`localgit`+`remotegit` → `git`) can look fine to a counsel rubric while inventing catalog debt. Certainty must mean “survived evidence pushback,” not “another CoT liked the wording.” That is why Cluster RLM is the **auditor in the propose → audit → revise loop**, not the walk itself.

## Algorithm (target)

```text
package_roles + graph
  → doors = packages with role entrypoint | server
  → mechanical_grouping.yaml (door-walk seed in Go)
  → typology_slice_grouping CoT: merge_ids + merge_packages + merge_intents
  → compose slice_grouping_proposal.yaml
  → typology_slice_grouping_audit RLM: one pass over the full list
  → revise / sticky reject / demote overlays to nicknames
  → write slice_grouping_verdicts.yaml
  → typology_slice_catalog (catalog only; fold only accept) → refined catalog YAML
  → architecture → human-intervention journey / PR counsel
```

Two doors never merge. Shared packages are not “won” by the first walk; they stay shared unless evidence says otherwise. Shared is not the same as library: only technical roles (dto, config, exec_runner, observability, and similar) are library by role. Mechanical product clumps are seed hints only; a CoT merge still needs `accept`.

Cluster audit `accept` requires evidence that cites every package path in the row; otherwise Go demotes the verdict to `overlay` so thin theme merges cannot fold the catalog.

## What RLM still owns elsewhere

- **Package inspect RLM:** role validation against AST context (`typology_inspect`).
- **Slice ledger RLM:** evidence-first objectives (`typology_slice_meaning`).
- **Cluster audit RLM:** membership challenger over the full proposed-merge list (`typology_slice_grouping_audit`). Not a second clusterer.

## Out of scope

- Replacing the mechanical door-walk with RLM
- Clustering as a pure series of RLMs with no CoT proposer
- Human-intervention / SliceBinding completion changes in this slice

## Status

Seed implemented in Typology `BuildMechanicalGrouping` door walks. Majordomo runs slice-grouping CoT plus full-list grouping-audit RLM before slice catalog assemble. Counsel-only WeightedScore is no longer the merge pass gate.
