# Staging and Classification

*Majordomo — repository operations for evolving software.*

Staging and classification turns a raw PR diff into structured review tasks. The entrypoint is `scripts/git-diff-prep.py`.

This page is for engineers tracing how `git-diff-prep.py` selects, routes, and packages files for review.

## ⚠️ Inputs

| Parameter | Default | Description |
|---|---|---|
| `base-branch` | `origin/master` | Branch to diff against |
| `staging-dir` | _(required)_ | Output directory for task payloads and manifests |
| `--routing` | _(optional)_ | JSON file with routing overrides |
| `--agent-context` | _(optional)_ | JSON file with global and scoped review context (see [Inject team context](09-customising-the-review.md#inject-team-or-domain-context-into-the-reviewer)) |

## ⚙️ Processing Steps

### 1. Detect changed files

```bash
git diff origin/master...HEAD --name-only
```

### 2. Apply exclusions

The script drops files that are not useful for review tasks: lock files, minified assets, compiled binaries, media files, and submodule paths.

### 3. Route files to skills

Each file is matched against routing rules in order. The first matching rule wins.

Default routing sends source code to `pr-review-code`, markdown and RST files to `pr-review-docs`, and config files (YAML, TOML, JSON, INI, etc.) to `pr-review-conf`. Tests have no default routing — add explicit routing in `.majordomo-config.groovy` to include them.

### 4. Build dependency context

For code files, the script calls `dep_clusters.py` to group files by import relationships. For markdown files routed to `pr-review-docs`, it calls `doc_clusters.py` to group files by markdown link relationships and build a `corpus-index.json` from all `.md` files in the repository. Both results are embedded in their skill's batch manifests.

### 5. Build per-file task inputs

For each reviewable file, the script gathers both diff and current content when size allows.

```bash
git diff origin/master...HEAD -- <file>
git show HEAD:<file>
```

Task mode selection:

- `full_and_diff`: combined file content + diff is under 500 lines
- `diff_only`: diff is under 300 lines but full content is large
- `diff_chunk`: diff exceeds 300 lines; split into 300-line chunks

Each task is written as a text payload in the staging directory.

### 6. Write manifests and batch plan

The script writes `manifest.json` at the top level, per-skill and per-batch `manifest.json` files in each skill and batch subdirectory, and a single `batch-plan.json` that dispatch reads to determine execution order.

### 7. Create synthesis batches

The script creates one batch per synthesis skill: `pr-review-summary`, `pr-review-technical`, and `pr-review-blast-radius` (only when reverse dependencies exist). These batches include dependency clusters and reverse dependency metadata so synthesis agents can reason across the full PR.

## 📦 Outputs

The staging directory contains per-file task payloads, per-skill and per-batch manifests, and one `batch-plan.json` consumed by dispatch.
