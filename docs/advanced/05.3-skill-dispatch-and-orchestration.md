# Skill Dispatch and Orchestration

*Majordomo — repository operations for evolving software.*

Dispatch executes batch manifests (JSON files describing which files and skills to process in one batch) and collects outputs into skill-level artifacts. The main dispatcher is `pipelines/scripts/copilot-dispatch.sh`, coordinated by the review orchestrator (`majordomo orchestrate` in Go, or a control-tower workflow step).

This page is for engineers operating the dispatch layer or tuning wave concurrency and scoring loop limits.

## 🔄 Execution Model

The pipeline runs review work in waves.

### Wave 1: Parallel file review and synthesis start

Initial batches for file-review skills run in parallel. Synthesis skills can also start from their own manifests when prerequisites are satisfied.

### Wave 2: Remaining file-review batches

Remaining file-review batches run per plan order.

### Wave 3: Quality loops for synthesis outputs

Summary and technical outputs go through score-feedback loops (write-then-score cycles that retry until quality threshold or iteration cap) until they pass thresholds or reach iteration limits.

## ⚙️ Per-Batch Behavior

For each batch manifest, dispatch:

1. Reads manifest metadata and task payload file paths.
2. Runs the mapped skill agent for each task.
3. Collects per-task outputs.
4. Writes batch-level aggregate output.

Conceptual invocation:

```bash
copilot-dispatch.sh \
  --skill pr-review-code \
  --mode file-review \
  --staging batch_000/
```

## 📦 Aggregation

After all waves complete, finalize collects per-file markdown reports, skill-level findings artifacts, and synthesis documents (`summary.md`, `tech-review.md`, and `blast-radius.md` when applicable). `md-to-html.py` converts the synthesis documents to self-contained HTML, and `review-to-junit.py` produces JUnit XML for CI test reporting.

## 🎛️ Control Knobs

| Variable | Default | Effect |
|---|---|---|
| `SUMMARY_MAX_ITERATIONS` | `5` | Maximum summary write→score attempts |
| `SUMMARY_PASS_SCORE` | `15` | Minimum score to accept without retrying (max 23) |
| `TECH_MAX_ITERATIONS` | `3` | Maximum technical review write→score attempts |
| `TECH_PASS_SCORE` | `11` | Minimum score to accept without retrying (max 14) |

Parallel wave concurrency is configured via orchestrator env (e.g. `COPILOT_WAVE_CONCURRENCY`) — see the control-tower config or `majordomo orchestrate` flags when implemented.
