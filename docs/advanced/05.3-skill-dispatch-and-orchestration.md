# Skill Dispatch and Orchestration

*Majordomo — repository operations for evolving software.*

Dispatch executes batch manifests (JSON files describing which files and skills to process in one batch) and collects outputs into skill-level artifacts. The dispatcher is `pipelines/scripts/agent-dispatch.sh` (OpenCode), coordinated by `majordomo orchestrate`.

This page is for engineers operating the dispatch layer or tuning wave concurrency and scoring loop limits.

## 🔄 Execution Model

The pipeline runs review work in waves via `majordomo orchestrate`.

### Wave 1: Parallel file review and synthesis start

Initial batches for file-review skills run in parallel. Synthesis skills can also start from their own manifests when prerequisites are satisfied.

### Wave 2: Remaining file-review batches

Remaining file-review batches run per plan order.

### Wave 3: Quality loops for synthesis outputs

Summary and technical outputs go through score-feedback loops (write-then-score cycles that retry until quality threshold or iteration cap) until they pass thresholds or reach iteration limits. Optional technical deep follows tech-review.

## ⚙️ Per-Batch Behavior

For each batch, orchestrate calls `majordomo dispatch` (or `agent-dispatch.sh` directly):

1. Reads manifest metadata and task payload file paths.
2. Runs OpenCode with the mapped skill.
3. Collects per-task outputs.
4. Writes batch-level aggregate output and a checkpoint.

Conceptual invocation:

```bash
majordomo dispatch <pr> <staging-batch-dir> <output-dir>
# or with a mode flag:
majordomo dispatch <pr> <staging-dir> <output-dir> --summary
```

Set `MAJORDOMO_BIN` (or put `majordomo` on PATH) so summary/technical modes can run `majordomo report all-diffs`.

## 📦 Aggregation

After all waves complete, finalize collects per-file markdown reports, skill-level findings artifacts, and synthesis documents (`summary.md`, `tech-review.md`, and `blast-radius.md` when applicable). `majordomo report html` converts the synthesis documents to self-contained HTML, and `majordomo report junit` produces JUnit XML for CI test reporting.

## 🎛️ Control Knobs

| Variable | Default | Effect |
|---|---|---|
| `SUMMARY_MAX_ITERATIONS` | `5` | Maximum summary write→score attempts |
| `SUMMARY_PASS_SCORE` | `15` | Minimum score to accept without retrying (max 23) |
| `TECH_MAX_ITERATIONS` | `3` | Maximum technical review write→score attempts |
| `TECH_PASS_SCORE` | `11` | Minimum score to accept without retrying (max 14) |

Parallel wave concurrency is configured via `majordomo orchestrate --concurrency` (and related env).
